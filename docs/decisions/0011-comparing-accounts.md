# 11. How accounts are compared fairly (status: accepted 2026-11-12)
**Decision:** the multi-account comparison (milestone M10) shows numbers that are comparable and honest, stays local, and says what it does not know. (0008 is reserved for the local-only guard, issue 37; 0009 and 0010 are the IBKR decisions.)

1. **Headline per account: money-weighted.** IRR of the account's real dated flows plus its ending value, and *excess IRR*: that IRR minus the IRR of the same deposits and withdrawals put into the benchmark (decision 0007). Time-weighted return and Sharpe are shown only as secondary figures and labelled **estimated** unless the month-end values are exact (statement-based). The data-quality badge on each row says `exact` (statement ending value, reconciliation checks pass, no inferred income) or `estimated`, with the as-of date.
2. **Different start dates: aligned windows.** Compare over YTD, 1y, 3y, 5y and since inception. An account that does not cover a window shows **n/a**, never a shortened number. A windowed IRR needs the account's value at the window start as an opening flow; that value is a reconstructed month-end, so **windowed figures are labelled estimated** even where since-inception IRR is exact. Windows under a year are not annualized beyond what the metrics already do.
3. **Wrappers: all figures are pre-tax.** The page never says a taxable account "beat" a Roth or IRA on an after-tax basis, and says so on the page. Wrapper is a grouping and label, not an adjustment.
4. **Combined views** (all, by brokerage, by owner, by wrapper): a transfer between two of the household's own accounts is **external for each account alone** (a withdrawal from one, a deposit into the other) but **internal in a combined view** that contains both ends, so it is netted out. If only one end is in the group, it stays an external flow. Matching uses the date window and amount (cash) or symbol and quantity (in-kind), with the importer's `transfer_hint` as a hint only; **unmatched candidates are listed, not guessed.** Closed accounts contribute their history up to closing. A group is valued on one common end date; if a member's ending value is not as of that date, the group is refused and the account named.
5. **Benchmark:** one chosen benchmark drives the headline excess IRR (default VTI). Extra comparisons (the report's `--also`, and the M5 registry, issue 53) appear as additional columns, never replacing the headline.
6. **Privacy:** the comparison is local, like the performance report. It is written to `exports/` (gitignored, mode 0600), never published as an artifact and never sent over Telegram or SMS. Registry, last digits and statement values stay in `.data/`. Tests and docs use invented data only. Only ticker symbols and date ranges go to price services.
7. **Scope:** this is *performance*. Holdings, drift, trades and withdrawable cash belong to the IBKR operations page (issue 82); components may be shared, scopes are not merged.

**Known limits:** estimated month-end values (the history omits reinvestments); a price series is split-adjusted closes, so unusual corporate actions can distort; a very short history gives noisy numbers and is flagged; IRR says nothing about the risk taken. Financial output is information, not investment advice.
